## 1. Foundations

### 1.1 Scalar — S/M
The OpenAPI 3.2 document is emitted from the spec and served as a static file (`/openapi/v1.yaml`, Development). Add
**Scalar.AspNetCore** (MIT) to each API, `MapScalarApiReference(o => o.WithOpenApiRoutePattern("/openapi/{documentName}.yaml"))`,
and a `WithUrlForEndpoint` display text on the API resources so the dashboard links to it. Tried 2026-10-08, then
reverted:

- **Renders our documents**: both, as OpenAPI 3.2.0, with every operation and schema. They use no 3.2-only feature yet.
  The `itemSchema` of SSE (§6) would be the first.
- **Fit to ship**: 2.17.14 is marked trimmable and AOT-compatible, without `RequiresUnreferencedCode` or
  `RequiresDynamicCode`, and serves its bundle (`scalar.js`, 1.2 MB) from the assembly. On load the page requested its
  own origin only ("Ask AI" and "Generate MCP" not clicked). Its page needs a CSP of its own with a nonce
  (`WithNonce()`, 3.3).
- **Dev stage for external developers**: the Public API, switched by configuration (`ApiReference:Enabled`) instead of
  `IsDevelopment()`, on through the stage's ConfigMap in `SpatialFocus/Infrastructure`, off in production.
  `Scalar.Aspire` is no option there: its container exists only while the AppHost runs.
- **Try it**: works against the anonymous Public API from the page's own origin (no `servers` entry, so no CORS). The
  Admin API answers 401: Scalar fills in only the schemes the document declares, today `BearerAuth`. A login needs an
  `oauth2` code-flow scheme in the spec and a public Keycloak client (code + PKCE, Scalar's redirect URI, the
  `admin-api` audience). For the Public API it comes with 8.1.
- **Known gaps**: the user search shows as `POST` while the server answers QUERY (emitter.md, task 4). Example values
  are Scalar's placeholders until the spec carries `@example` and `@opExample`.
- **Tests**: `/scalar/` and `/openapi/v1.yaml` answer 200 with the switch on and 404 with it off, in the Admin
  integration tests and in a first `Public.Api.IntegrationTests` (8.1).

### 1.2 ProblemDetails enrichment — S
Unhandled 500s go through `AddProblemDetails()` + `UseExceptionHandler()`. Open: enrich every problem with `traceId`,
`requestId` and `instance` (`"GET /path"`), so a problem the UI shows leads to its trace (SSW pattern).

### 1.3 Mapperly for entity → DTO ❓ — S
Mapperly maps view model ↔ contract in the Web forms. Handlers project entities into DTOs by hand, one `Select` per
query, which the EF precompiler can follow. Decide with the Public stations read model (§10) whether Mapperly's
`IQueryable` projections earn their place; Vogen ids need small user mapping methods.

### 1.4 Custom OTel metrics (API) — S/M
**Goal:** first-class custom metrics next to the built-in ones, a pattern the cache and the events reuse.

- One telemetry class per concern on **`IMeterFactory`** (+ `TimeProvider` for durations), a DI singleton, never static
  meters. practical-dotnet-aspire's `CommandHandlerMetrics` is the reference shape.
- Semconv naming: lowercase dot-namespaced (`focustemplate.stations.observations`), UCUM units (`"s"`,
  `"{observation}"`), durations as histograms in seconds.
- Register at the feature's DI extension, `services.AddOpenTelemetry().WithMetrics(m => m.AddMeter(...))`, so
  ServiceDefaults stays generic.
- **Exemplars**: measurements inside an active `Activity` link metric points to traces in the dashboard.
- Unit-test with `MetricCollector<T>` (Microsoft.Extensions.Diagnostics.Testing).

## 2. Domain

### 2.1 Events — M
Entities raise no events. A handler that needs a follow-up publishes a Mediator `INotification` after its
`SaveChanges`; notification handlers log their failures and never throw into the request. At-most-once, documented; the
outbox (§6) is the durability upgrade. First use: an observation over a station's threshold raises an `Alert` (§10).

### 2.2 Value objects as EF complex types ❓ — S/M
A complex type is a plain record, so it fits plain entities. Candidate: the station's thresholds (`MinTemperatureC` /
`MaxTemperatureC`, flat columns today) as one `TemperatureRange` (`ComplexProperty`), with its rule (min at most max) in
one place. Child collections: `OwnsMany(...).ToJson()`.

### 2.3 More architecture tests — S
`FocusTemplate.ArchitectureTests` checks the read/write context rule and the model's sentinels by reflection.
Candidates: the two `Shared` projects never reference each other; `Primitives` references no EF Core; one feature's
handlers never reference another feature's; an `AutomationId` on every interactive MAUI control.

**Resx pairs** (localization): a text with values is a generated method (`localizations.NoGroup(id)`), whose parameters come
from the English text, so the code always passes what the English needs (`GenerateFormatMethods`, from
[ycanardeau/ResXGenerator#13](https://github.com/ycanardeau/ResXGenerator/pull/13) in the local package). A translation
with an index the English lacks, or a stray brace, still throws a `FormatException` at run time, a 500 in the API or a
render error in the Web app. A test reads every neutral resx and its `.de.resx` in Web, API and `Admin.Shared` and
checks per key: both files have it, the translation has the same placeholders (`{0}`, `{1:g}`, and FluentValidation's
`{PropertyName}` style in `CustomLanguageManager.resx`), and a text with values parses (`CompositeFormat.Parse`).

## 3. Platform features

### 3.1 FusionCache — M
**Goal:** L1 (memory) + L2 (distributed) + cross-node invalidation, observable in the dashboard.

- **ZiggyCreatures.FusionCache** (MIT): L2 Redis via Aspire `AddRedis` + `Aspire.StackExchange.Redis` +
  `WithDistributedCache`.
- **Backplane** (`…Backplane.StackExchangeRedis`) for cross-node L1 invalidation, the reason to pick it over the
  built-in `HybridCache`, which has none (dotnet/runtime#125602), nor fail-safe, soft timeouts or eager refresh.
- **Tagging** demo: a cached read carries a tag, a write calls `RemoveByTag(...)`. Optionally `.AsHybridCache()`, so app
  code targets the Microsoft abstraction.
- **OTel**: `ZiggyCreatures.FusionCache.OpenTelemetry`.
- **Scale-out proof**: `WithReplicas(2)` and a test that instance B sees instance A's invalidation.
- The same Redis serves 3.2's server-side sessions and Data Protection key ring.
- ❓ `Features:Cache`? Redis adds a container to every `aspire start`.

### 3.2 Authentication — the open half — L
The Admin core landed (`docs/authentication.md`, `docs/authorization.md`). Open:

- **Data Protection key ring**, shared and persisted (`AddDataProtection().SetApplicationName(…).PersistKeysTo…` on
  Redis, blob storage or the database). Without it a recreated BFF container signs everyone out, and with two replicas
  a callback that lands on the other one fails ("Unable to unprotect the message.State"). Needed at the first
  deployment.
- **Server-side sessions**: `ITicketStore` (`CookieAuthenticationOptions.SessionStore`) on Redis/FusionCache keyed by
  `sid`, so sessions are revocable and the tokens leave the cookie. A second BFF instance also needs a refresh lock
  across instances, the token management's `IUserTokenRequestConcurrencyControl` being per process.
- **Backchannel logout** (no built-in in .NET, aspnetcore #4659): validate the `logout_token` (`typ=logout+jwt`,
  `events`, `sid`/`sub`) and revoke the matching ticket. Reference: damienbod/keycloak-backchannel.
- **Refresh-token revocation on logout**: `HttpContext.RevokeRefreshTokenAsync()` in `/bff/logout` before the
  end-session redirect, so it does not depend on the browser following it.
- **`/bff/user` can answer 500 instead of 502**: it only catches `HttpRequestException` from its call to the API. A
  timeout or an open circuit of the resilience handler (`TimeoutRejectedException`, `BrokenCircuitException`) or an
  unreadable body (`JsonException`) escapes, and the BFF has no exception handler. Catch them as "no answer", or route
  the BFF's client through `NoAnswerHandler` as the WASM client does.
- **A failed login callback is a 500**: there is no `OnRemoteFailure`, so an expired correlation cookie (15 minutes,
  Keycloak's login form lasts 30), a replayed `/signin-oidc` (Back button) or `error=…` from Keycloak throws. Handle it
  with a page and a retry link, not a redirect to `/bff/login`, so a persistent failure (wrong secret, `access_denied`)
  cannot loop.
- **Logout after a Keycloak restart**: a surviving BFF session sends an `id_token_hint` the new Keycloak rejects
  ("Invalid parameter: id_token_hint"). `Features:PersistentLocalKeycloak` avoids it, the default does not.
- **Tests for the security guards**, which can all be weakened with the suite staying green: the logout `sid` check, the
  returnUrl filter, the token transform's route filter, cookie isolation, stripping `Authorization`, signing out on a
  refused refresh. A `FocusTemplate.Admin.Web.Bff.IntegrationTests` project (`WebApplicationFactory`, a test scheme, a
  stub destination), plus one API test with a locally signed JWT, so `sub` provably survives `MapInboundClaims = false`.
- **A login popup** in place of the full redirect when a proxied call answers 401 (the `TODO` in
  `Web.ClientServiceDefaults/ServiceCollectionExtensions.cs`): the handler calls a notifier, a layout component or the
  `ErrorBoundary` of 4.1 shows it.
- **Publish**: a Keycloak with the realm baked into its image. Today publish takes an external realm from parameters.
- **Public API + mobile**: a Keycloak public client, code + PKCE, bearer tokens to `Public.Api` (8.1).

### 3.3 Security headers and a CSP — M
No response carries a security header today: no CSP, `frame-ancestors`, `nosniff`, `Referrer-Policy` or HSTS, neither
from the BFF nor from the ingress. Blazor WebAssembly generates no policy and no hashes. Only Blazor Web Apps send
`frame-ancestors 'self'` by default, which this app is not.
- **Where**: a `Content-Security-Policy` header from the BFF, which serves `index.html`. A `<meta>` tag cannot carry
  `frame-ancestors` or `report-to`. The CSP depends on the build output and the app, so the ingress cannot set it.
- **Package**: [NetEscapades.AspNetCore.SecurityHeaders](https://github.com/andrewlock/NetEscapades.AspNetCore.SecurityHeaders)
  (Andrew Lock, MIT, the most used one), in the BFF with `AddDefaultSecurityHeaders()` plus the CSP builder, in the API
  with `AddDefaultApiSecurityHeaders()`. Its tag helpers hash only Razor-rendered scripts, so the hashes of the static
  `index.html` are ours. Its defaults get a review: `X-Frame-Options: Deny` repeats `frame-ancestors 'none'`, COEP
  `credentialless` against the analytics proxy, COOP `same-origin` against a login popup (3.2).
- **Policy**: `default-src 'self'`, `script-src 'self' 'wasm-unsafe-eval'` plus the inline hashes, `style-src 'self'
  'unsafe-inline'` (Blazor writes style attributes through `setAttribute`, Radzen's `Style` among them), `img-src 'self'
  data:`, `font-src 'self'`, `connect-src 'self'` (API, `/_otlp` and `/_analytics` all go through the BFF), `object-src
  'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`, and `upgrade-insecure-requests` behind TLS.
- **Inline scripts**: the import map, which the build fills in and every new fingerprint changes, and the loading
  screen's texts. The BFF reads the published `index.html` at startup, hashes each inline `<script>` and lists the hashes
  in `script-src`, so no hash is kept by hand.
- **Development**: Hot Reload's browser refresh injects a script and opens a WebSocket, so Development sends the policy
  as `Content-Security-Policy-Report-Only` (the package's policy selector), every other environment enforces it.
- **The other headers**: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` and a small
  `Permissions-Policy` from the package. HSTS where TLS ends: at the ingress in a deployment (the cluster's nginx,
  `SpatialFocus/Infrastructure`) and in the local nginx ingress of `Features:TlsOffloadingIngress`, so the package's HSTS
  stays off in the BFF.
- **Tests**: the E2E fixture fails a test on any CSP violation in the browser console, an E2E test checks the headers on
  `/` and on a proxied call, and a BFF integration test covers the hashing (with the project of 3.2).
- Microsoft's guide: [Enforce a Content Security Policy for ASP.NET Core Blazor](https://learn.microsoft.com/aspnet/core/blazor/security/content-security-policy).

- **Built-in `HybridCache` alone** — no backplane, so other nodes' L1 stays stale (3.1).
- **Swashbuckle, runtime `AddOpenApi()`** — the OpenAPI document is emitted from the spec.
- **API versioning (Asp.Versioning)** — deferred until the template has consumers that need it.
- **EF InMemory provider for tests** — real Postgres via Testcontainers stays the rule.
- **Blazor Hybrid for the mobile client** — the Public vertical has a native mobile UX. Revisit only if a public *web*
  client joins it.

## 10. Sample domain — weather stations *(planned 2026-09-22)*

**Why:** `WeatherForecast` alone is too thin to show anything. The weather sample grows instead of being replaced.

**On disk:** the entities `Station` (`StationId` uuid v7, self-assigned; `OwnerId : UserId`; `Code` unique per owner;
`Location` as a PostGIS `geography` point; `Status` as the native enum `station_status`; temperature thresholds),
`Observation` (int64 identity, append-only), `Alert` (`alert_kind` enum, raised and resolved) and `WeatherForecast`
with its `StationId`. The seed creates two stations. No slice serves them yet.

**Audiences:** Admin administers stations scoped to their owner (a foreign station is 404, not 403); Public reads
`Active` stations with current values, forecasts and open alerts, paged and optionally within a radius.

**Rules**, in the handlers and answered with a 409 case: `Retired` is final; `Maintenance` only without open alerts;
code and location change only in `Active` or `Maintenance`. Each rule lives in one layer: shape in the spec (400),
access in the handler (404), rules in the handler (409), the database last (the `(OwnerId, Code)` index and the row
version, 409).

**Order:**
1. **Admin stations slice**: `src/admin/spec/stations/stations.tsp` (create, edit, relocate, thresholds, start
   maintenance, reactivate, retire, delete), a `Stations` permission enum, owner scoping in every handler,
   `[Timestamp] Version` for optimistic concurrency (**Optimistic concurrency** in `docs/database.md`, no entity uses it yet), list
   and detail pages.
2. **`observer` resource**: a worker project `src/FocusTemplate.Observer` behind `Features:Observer`, `ICurrentUser` =
   `WellKnownUsers.System`, periodic observations for active stations.
3. **Alerts**: an observation over a threshold raises an `Alert` through 2.1's pattern.
4. **Public read model**: `src/public/spec/stations/stations.tsp`, active stations paged, optional radius
   (`EF.Functions.Distance` on the geography column), latest observation, forecasts, open alerts (8.1).

Postgres enums: adding a value is an automatic `ALTER TYPE … ADD VALUE`, dropping or renaming one is hand-written SQL in
the migration.
