# Localization

- Every text a user reads comes from a resx: English in the neutral file, German in the `.de.resx` beside it, changed
  together.
- `I{Name}Localizations` and the class behind it are generated by the `Aigamo.ResXGenerator` package from the neutral
  resx at build time, one property per key. They are not in the repository. A new key becomes a property at the next
  build, and nothing of it is written by hand.
- A component's resx sits next to it and is read through `@inject I{Component}Localizations L`. An API interface has one
  resx named after its folder (`Groups.resx`), read through `I{Interface}Localizations localizations`.
- A text with values takes `{0}` (`{0:g}` for a date) and becomes a method with a parameter per value,
  `localizations.NoGroup(command.Id)`. Its translation uses no index the neutral text lacks.
- A service or view model takes its texts in its constructor, a shared rule as a parameter.
- A resx read by key (permissions, contracts) gets `SkipFile` in its project file.
- Each host registers `AddAdminSharedLocalization()` beside its own `UsingResXGenerator()`.
- A contract's field names and pattern messages go into the resx named after the contract type in `Admin.Shared`
  (`DemoProfileRequest.de.resx`, keys `Code` and `Code.pattern`).
- Data, logs and exception messages stay untranslated.
- A new language goes into `Cultures.Supported`, the realm's `supportedLocales` and the projects' resx patterns.
